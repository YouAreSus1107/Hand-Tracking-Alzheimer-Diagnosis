# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Project Overview

Camera-based motor screening suite for early cognitive-decline detection. Uses OpenCV + MediaPipe to run clinical-style tests: finger tapping (max-speed + paced modes) and spiral tracing via 21-landmark hand tracking, plus an oculomotor pro/anti-saccade test via 478-landmark face/iris tracking. Originated as a fork-style clone of a Unity hand-mirroring project; the Unity side is retired (local `archive/` only, git-ignored) and only the Python suite is developed.

## Running

```bash
python install.py                 # one-time setup: .venv + deps + model download
.venv/Scripts/python launcher.py  # control hub at http://127.0.0.1:8770 (Windows path)
```

`install.py` (stdlib-only) creates `.venv/`, installs `requirements.txt` into it, and downloads any missing MediaPipe model bundles (notably `model/face_landmarker.task`, which is not committed). Double-click `setup.bat` on Windows for the same thing; `run_hub.bat` prefers the venv interpreter automatically. Users managing their own environment can still `pip install -r requirements.txt` directly.

Or run tools directly with the venv interpreter: `.venv/Scripts/python screening_tests/finger_tapping.py`, `python screening_tests/spiral_test.py`, `python screening_tests/oculomotor_test.py`, `python core/hand_tracking.py`. Run directly and each still prompts for a camera source (`1` webcam / `2` IP stream URL); launched from the hub they take it from the dashboard's camera chip instead and never ask. Press `q` to quit. Audio cues play via `winsound` on Windows (system-default device) and `sounddevice` (PortAudio) elsewhere. Gaze-engine unit tests: `python screening_tests/tests/test_gaze.py`.

## Architecture

- **`launcher.py`** — stdlib-only web server (port 8770). Serves the dashboard frontend from `launcher_web/` (`index.html`, `styles.css`, `app.js`, `dev.js`, `i18n.js`, `i18n.zh.js`, `background.js`, `hand3d.js`) and launches each tool via `subprocess.Popen` in its own console (`cwd=BASE_DIR`, `env=_camera_env()`); one tool at a time may hold the camera. **Camera source is chosen in the UI**, not at a console prompt: `camera_setting()`/`set_camera_setting()` persist `{mode,index,url}` to `.launcher_settings.json` (git-ignored), the value rides along in `/api/status` so the chip stays in sync on the existing 3 s poll, `POST /api/camera` updates it, and `_tool_env()` hands it to the next launched tool. It applies at launch, so changing it mid-run affects the next start. **Overlay language rides the same rails**: `lang_setting()`/`set_lang_setting()` persist it, `POST /api/lang` updates it (the dashboard's `onLang()` hook posts on every switch, and seeds it once at init since that hook only fires on change), it rides along on `/api/status`, and `_tool_env()` sets `HAND3D_LANG` beside `HAND3D_CAMERA`. `/api/launch` also carries `lang` in its body and that overrides the stored value, so a switch made a moment before Launch cannot lose the race against the POST that persists it. Static files resolve from `RESOURCE_DIR` (`sys._MEIPASS` when frozen, else repo root); tool scripts + PID file use `BASE_DIR` (real disk). `GET /api/session?id=` returns one session **with its `raw` recording** (`/api/sessions` strips `raw`); the id is matched against the `session_id` *inside* each file rather than used to build a filename, because on the published dashboard that query string is attacker-controlled. Packaging instructions in `docs/BUILD_LAUNCHER.md`. It also answers the **published dashboard**: `_authorised()` gates every request behind a server-side `Origin` allowlist plus an `X-Hub-Token` (`hub_token()`, kept in `.launcher_settings.json`) — a cross-origin `text/plain` POST arrives with no preflight, so CORS response headers alone would not be an access control, and `/api/dev/*` can flash firmware. `do_OPTIONS` answers Chrome's Private Network Access preflight; `GET /pair?return=<origin>` validates the return address against the same allowlist and redirects back with `#token=…` so nobody types a code; `--web` opens the published site already paired.
- **`launcher_web/`** — dashboard frontend served by `launcher.py`: `app.js` (UI, cards, status pills, launch/stop API, and the **camera-source chip** — a small `[data-cam]` slot rendered into the dashboard's "Screening Tools" head and every test page's action row, folding open into a radio/index/URL popover; one shared `camState`, rebuilt only when its signature changes so the 3 s poll does not churn the DOM, and never while a popover is open — a classic script so inline `onclick` handlers stay global; also renders the home **readings strip** — one tile per test showing that test's latest headline metric, band and spark, drawn from `/api/sessions` through the same `TREND` config the Analysis page uses, refetched when a run stops — the client-side **Analysis** longitudinal view — whose dot colour is now the verdict the test itself recorded (`metrics.status`/`label`, falling back to the page's provisional bands), and whose chart points and **session calendar** are the way into `report.js` — and the static **Why This** differentiation page from in-file data arrays), `dev.js` (**Developer** page — glove toolchain pills, firmware compile/upload, live canvas scope, per-channel readouts, serial console; a classic script loaded after `app.js` so it shares its `I`/`toast()`/`reducedMotion` bindings, and `showPage()` starts/stops its ~100 ms poll so it only runs while visible), `report.js` (**session report panel** — a centred modal sheet on its own lighter slate palette (tokens scoped to `.report`, so the rest of the app is untouched); a classic script after `app.js`, sharing its `I`/`t()`/`ST`/`TREND`/`statusOf` bindings; a click on any chart dot or calendar row on the **Analysis** page delegates to `window.openReport(id)`, which fetches `/api/session?id=` and draws that one session: its own verdict, the actual recording (tapping distance trace with every accepted tap and the metronome beats, the traced spiral over the template it was aiming at, the saccade trials one at a time), every metric, and how it was recorded. Each renderer guards on missing keys because `results/` holds legacy shapes — 5-column spiral samples, records with no `status`, `scoreable:false` sessions that lead with `reason`). The calendar (`sessionCalendar()`, `.cal-*`) indexes the card's sessions by date — a month grid of the months that actually hold runs beside a scrolling list of the chosen day; picking a day or month calls `renderCalendar(key)`, which rebuilds only that one `<section id="cal-<test>:<mode>">` from `analysisSessions` rather than re-rendering every card, and `report.js` calls `window.revealSession(id)` so stepping through the panel with the arrows brings the calendar to the session being read., `background.js` (WebGL reaction-diffusion), `hand3d.js` (Three.js hand model, ES module),
  `i18n.js` + `i18n.zh.js` (**English / 繁體中文 switch**, see below).
- **Hub i18n** — `i18n.js` is the mechanism, `i18n.zh.js` the Chinese-only dictionary; both load before `app.js` (which renders during parse). Only Chinese is stored: English stays in `index.html` and in the JS source strings, and `applyStatic()` snapshots each tagged element's English markup on first run so switching back restores it. Three lookups: `tKey()` for `data-i18n` blocks in the markup (dotted keys, values keep the same inline `<a>`/`<strong>`/`<code>`), `t()` for strings rendered from JS (**the English source string is the key**, with `{name}` params), and `tMsg()` for text the server sends — `launcher.py` / `core/glove/serial_io.py` messages are matched by an exact/regex/suffix table rather than translated in Python, and anything unmatched shows as sent. `onLang()` re-render hooks live at the bottom of `app.js` and `dev.js`; `t` is the translator, so never shadow it with a loop variable (`TOOLS.forEach(tool => …)`). House style: translate the prose, keep the term — metric acronyms (CV%, SPARC, SMD), identifiers, paths and citations stay Latin. The switch also sets the language of the **OpenCV test overlays** — see the `core/i18n.py` bullet below; finger tapping is translated end to end, spiral/oculomotor/hand-tracking land in phase 2 of `docs/OVERLAY_I18N_PLAN.md`. The **Why This** page (nav pill `data-page="why"`, rendered by `renderWhy()`) states how the suite differs from other at-home screeners — pillars and a suite-vs-consumer-vs-TAS-Test comparison matrix; copy is sourced from `research/README.md`, `research/01-webcam-hand-motor.md`, and `docs/ROADMAP.md §1 & §7`. Edit these directly; the launcher serves them no-cache so refreshes pick up changes.
- **`tools/`** — publishing. `build_web.py` assembles `web-build/` (frontend + `assets/`, footer rewritten, `web_static/static-api.js` injected ahead of `app.js`) and calls `build_release.py`, which `git archive`s **HEAD** into `web-build/download/HandScreening-Setup.zip` (~8 MB; it warns when the tree is dirty, because the bundle ships the commit and not the working tree) with a `latest.json` the download button reads its size from. **`static-api.js` is a connector, not a mock**: it probes `127.0.0.1:8770/api/hub` and, once paired, forwards every `/api/*` call to the visitor's own hub with the token, so the public page really does launch the tests; with no hub it falls back to canned payloads and shows the download card. State lives on `body[data-hub]` (`probing`/`connected`/`unpaired`/`offline`), which `styles.css` keys the `#get-app` card off — the local hub never loads the connector, so that card cannot appear there. Deploy: `firebase deploy --only hosting`.
- **`core/remote/`** + **`participant/`** — **remote sessions**, a **paused prototype**: a helper mints an invite link in the hub, a participant opens it on their own phone, the test runs *in their browser*, and only the metrics come home. Plan and handover: `docs/REMOTE_SESSION_PLAN.md` (§9 is the map). Host side, all stdlib: `invites.py` (token minting, `state()`/`spend()`, and the `TESTS` registry mapping a tool key to the `test`/`mode` strings `core/session.py` actually writes — they are *not* the same vocabulary), `ingest.py` (**the security boundary**: `BANNED_KEYS` rejects `raw`/frames/landmarks/video at any depth, the mode must match *the invite's* mode rather than the test's mode list, `device` is allowlisted, `already_have()` de-dupes), `store.py` (`.remote_sessions.json` ledger, git-ignored — it holds live tokens and participant names), `relay.py` (Firestore REST: a pure value-typed codec plus one networked `fetch()`; the hub signs in **anonymously** and uses that uid as `helper_uid`). Hub surface: `GET/POST /api/remote/*` in `launcher.py`, the **Remote** nav page (`launcher_web/remote.js`, `#page-remote`, `.rs-*`), and `firestore.rules` (deployed). Accepted results are written through `save_session(source="remote", ...)`, so they appear in the Analysis view with no frontend change — remote filenames carry `session_id[:8]` because they arrive on the participant's clock and two can share a second. Participant side: `participant/` is served at `/s/<token>` (copied into `web-build/s/` by `build_web.py`), covering **finger tapping `big_and_fast` only** — in-app-browser check → consent → camera → framing gate → calibration → practice → trial → upload. **`participant/engine.js` is a port of `core/tapping/`, and Python is normative**: changing the Python means re-running `tests/make_vectors.py` and `tests/parity.mjs` (155 golden-vector checks). Three files describe one upload — the page, `firestore.rules`, `ingest.py` — and nothing makes them agree automatically, which is what `screening_tests/tests/test_remote_contract.py` is for; `test_remote.py` covers the rest. **Blocked:** Firebase Authentication has never been initialised on the project, so anonymous sign-in returns `CONFIGURATION_NOT_FOUND`; hosting is deliberately un-deployed.
- **`core/hand_utils.py`** — shared by all tools: `HAND_CONNECTIONS`, One-Euro filters (smooth landmark x/y; z left raw), `preprocess_for_mediapipe` (CLAHE + sharpen).
- **`core/hand_tracking.py`** — tracker + UDP broadcast of pixel-scaled landmarks to `127.0.0.1:5052`, format `L:[x1,y1,z1,...]` per hand.
- **`screening_tests/finger_tapping.py`** — tapping test run loop + rendering only; engine lives in `core/tapping/` (`modes.py` TapMode registry, `detector.py` calibrated hysteresis tap detection, `metrics.py` pure scoring functions, `audio.py` beep worker). Headline metric: CV% of inter-tap intervals. Beeps fire `AUDIO_LEAD` early to offset audio latency; beats run on an absolute grid.
- **`core/ui/`** — shared UI toolkit implementing `docs/UI_STYLE_GUIDE.md`: `theme.py` (tokens), `components.py` (PIL-overlay Canvas: panels, chips, buttons, toasts, sparkline), `anim.py` (easing). `components.py` also owns **font resolution**: a per-OS root list (Windows/macOS/Linux) searched for a bundled face first, then system faces, with the CJK stack tried ahead of the Latin one when the run is in Chinese. PIL does no per-glyph fallback, so a font *name* is not evidence — `_covers_cjk()` renders the probe character and compares it against `U+FFFE` (permanently unassigned, therefore always `.notdef`); an identical bitmap means no glyph. At import time a miss calls `i18n.set_render_capable(False, …)`, which degrades the whole run to English rather than painting tofu. The **mono stack stays Latin-only** (tabular figures are the point of it), so `Canvas.text()` silently demotes `mono=True` to the proportional stack for any string with wide characters — numbers keep their mono face, a translated label never asks the mono face for a glyph it lacks. First in the CJK list is `assets/fonts/NotoSansTC-Subset-*.ttf`, the one layer that does not depend on the user's machine: built by `tools/build_cjk_subset.py` from an **OFL** Noto Sans TC (never the proprietary `msjh.ttc`), subset to exactly the characters in `core/i18n_zh.py` plus ASCII — 82 kB a weight instead of ~9 MB. **Re-run that tool after adding Chinese strings**, or the new characters are missing from the bundle; `test_i18n.py` fails when they are. `build_web.py` skips `assets/fonts/` — the site never draws with it.
- **`core/i18n.py`** + **`core/i18n_zh.py`** — **overlay language** for the tools, the Python counterpart to the hub's `i18n.js`/`i18n.zh.js` and deliberately the same shape: only Chinese is stored, English lives in the source strings, an untranslated string degrades to English. `t()` takes the English source string as its key (`{name}` params, substituted by regex not `str.format` so a stray brace cannot raise mid-frame); `tk()` takes a dotted key with an English fallback, for the pre-split instruction blocks in `core/tapping/modes.py` and `core/gaze/tasks.py` whose Chinese line count differs. The language comes from `HAND3D_LANG` (set by `launcher.py`), else `.launcher_settings.json`, else `en`. **Translate at draw time only** — `modes.py`/`tasks.py`/`spiral/metrics.py` labels are also saved through `core/session.py` into `results/*.json` and `index.csv`, and translating them at the data layer would split the Analysis page's longitudinal history the first time somebody toggles the language. A few engine strings are formatted *before* they are stored (the tap-count `reason` in `core/tapping/metrics.py`), so they can be neither templated nor looked up whole: `ZH_RULES` matches those with a regex and `$1` group expansion, the same trick `tMsg()` uses on the hub side. `wrap(text, cols)` does the line breaking for both languages — Chinese has no spaces, so a `str.split()` word-wrap returns one unbreakable token that runs off the panel; it counts CJK as two Latin advances, breaks between characters, and honours the punctuation that may not start or end a line. Stdlib-only and import-cheap (it sits above the heavy-import block, and never imports PIL — the dependency runs `components.py` → `i18n`, not back). Plan: `docs/OVERLAY_I18N_PLAN.md`. Unit-tested in `screening_tests/tests/test_i18n.py`.
- **`core/session.py`** — shared results schema: one JSON per session in `results/` (git-ignored) + `results/index.csv`.
- **`core/camera.py`** — shared camera-source/open helper. The source normally comes from the launcher: `launcher.py` writes the dashboard's choice into the spawned tool's environment as `HAND3D_CAMERA` (`ENV_CAMERA`), and `preset_camera_source()` returns it so `select_camera_source()` skips the console prompt entirely — the prompt only appears when a script is run straight from a terminal. `core/hand_tracking.py` keeps its own prompt but checks the same preset first. Each probed backend/fourcc candidate costs a camera open (visible LED flash + ~1 s warm-up), so the combo that works is cached to `.camera_cache.json` (git-ignored) and tried first on the next run — steady state is one open. Ask for a frame rate via `open_capture(..., fps=60)`; setting `CAP_PROP_FPS` after opening renegotiates the stream and flashes the camera again.
- **`core/splash.py`** — stdlib-only console **loading screen** (brand header, weighted progress bar, stage + elapsed seconds), constructed **above** the `cv2`/`mediapipe` imports in every entry script: those cost ~2 s warm and ~10 s cold, and until they land nothing has printed, so the launcher's console looked hung. Entry scripts call `_splash.step()` between the heavy imports and `_splash.done()` after the block; `main()` no longer prints its own banner. Painted from a daemon thread over ANSI (VT enabled on Windows via `SetConsoleMode`), falling back to plain `Loading X...` lines when stdout is piped/`NO_COLOR`/dumb and to ASCII bar glyphs on a code page that cannot encode them. Stage weights (`IMPORT_STEPS`, `GAZE_IMPORT_STEPS`) mirror measured cold-import cost; within a stage the bar eases toward that stage's ceiling and only snaps on a real `step()`. Background + the machine-level fixes: `docs/COLD_START.md`.
- **`core/quiet.py`** — MediaPipe/TFLite native-log suppression. `from core import quiet` **must precede `import mediapipe`** (glog reads its env at load time); wrap task-graph creation in `with quiet.muted_native_stderr():` for the TFLite lines glog doesn't cover — it replays the captured text if creation raises, so real failures are never hidden.
- **`core/glove/`** — host stack for the wearable sensor glove: `protocol.py` (pure `G,seq,t_us,…` frame + `#GLOVE` banner parser, seq-gap accounting, ADC→mV/Ω math mirroring the firmware's integer arithmetic, plus per-channel `kind`/`r_fixed` metadata from the banner's `chan=` field), `force.py` (pure resistance→force via the **published Interlink FSR402 curve**, piecewise log-log — see `GLOVE_FIRMWARE_PLAN.md` §5b; readings outside the rated 0.2–20 N band are flagged, never presented as measurements), `flex.py` (pure resistance→**normalised bend** against a recorded span — §5c; there is no published curve for bend sensors, so this reports position within a span, never degrees, and badges the default span as uncalibrated), `imu.py` (pure milli-units→g/°·s⁻¹, tilt from gravity, and the **3.5–12 Hz tremor band power + peak Hz** — §5d; stdlib-only DFT evaluated at the band's bins, deliberately matching `core/spiral/metrics.TREMOR_BAND` so glove and camera tremor mean the same thing; returns `None` rather than a number below a 2 s window), `serial_io.py` (pyserial reader thread, VID-based board auto-detect, ring buffer, CSV recording to `results/glove/`; `derived()` routes each channel to `force.py` or `flex.py` by its declared kind). Firmware `firmware/glove/glove.ino` streams **12-bit** ADC at 100 Hz, **each channel with its own low-side resistor**, plus the **onboard IMU** as six signed integer milli-unit columns (`ax..gz`) when it initialises — the library is chosen by **one explicit `#define GLOVE_IMU_…` line at the top of the sketch** (LSM9DS1 / BMI270 / none — set it from the board's silkscreen), because `__has_include` auto-detection is invisible to arduino-cli's include resolver and silently builds without the library (§5d); a failed `IMU.begin()` omits the columns rather than publishing zeroes, and the banner names which IMU answered. The Developer page's **Motion** card (`/api/glove/imu` → `GloveReader.imu_summary()`) shows tilt, magnitude, per-axis bars and the tremor readout, and its toolchain row reports whether the library the sketch selected is actually installed (with install buttons for both). **Force sensors occupy the even analog pins** (`p<n>` on `A(2n)`); odd pins are reserved for flex. Fitted now: `p0`/A0 and `p1`/A2, both 10 kΩ. The banner drives all host-side scaling, so adding a sensor is a firmware table edit with no host or frontend change. Flashing gotcha: the bootloader re-enumerates on a *different* COM port — see `GLOVE_FIRMWARE_PLAN.md` §7.2. Engine unit-tested in `screening_tests/tests/test_glove.py` (no hardware needed). **pyserial is an optional dependency** — imported lazily so the launcher runs without it.
- **`screening_tests/spiral_test.py`** — self-paced air spiral tracing (no pacer dot), run loop + rendering only; engine lives in `core/spiral/` (`geometry.py` Archimedes spiral gen/resample, `metrics.py` pure scoring). Headline metric: movement-smoothness index from **SPARC** (Balasubramanian 2015); support: normalized jerk, velocity CV% (Schroter V-Rel), a bounded tremor-band readout, completion (data-quality gate). **Jitter is measured on the RAW fingertip** — the One-Euro smoothing in `hand_utils` is display-only and would erase it. Provisional bands; validation path = HandPD/NewHandPD. Plan: `docs/SPIRAL_TEST_PLAN.md`. Engine unit-tested in `screening_tests/tests/test_spiral.py`.
- **`screening_tests/oculomotor_test.py`** — pro/anti-saccade eye-movement test, run loop + rendering only; engine lives in `core/gaze/` (`tracker.py` Face Landmarker → smoothed iris `gaze_x` + uncalibrated vertical `ratio_y`, `calibrate.py` 3-point deadband + L/R map, `detector.py` pure saccade onset/direction/latency events, `metrics.py` pure scoring, `tasks.py` SaccadeTask registry, `fixation.py` fixation-stability analyzer). Headline metric: anti-saccade error rate %. Latency leads with Anti − Pro (cancels the fixed camera/display offset). A third block, "Part 3 - Hold Still", is a fixation-stability hold reporting RMS jitter, 2-D BCEA, and saccadic-intrusion rate (secondary readout). Plan: `docs/OCULOMOTOR_TEST_PLAN.md`.
- **`model/hand_landmarker.task`** / **`model/face_landmarker.task`** — MediaPipe model bundles (face model for the oculomotor test). All scripts resolve them via `__file__`-relative paths (`_REPO_ROOT / "model" / ...`), so they work from any cwd.

## Key Details

- MediaPipe **Tasks API** in VIDEO running mode (not the deprecated `solutions` API) — required for Python 3.12+.
- Screening tests add the repo root (and `core/`) to `sys.path` at the top of the file; keep that block first if editing imports. `finger_tapping.py` imports via the `core.*` package path.
- The tapping test flips the frame to selfie view (matches MediaPipe's handedness convention, so reported hand labels are true); `hand_tracking.py` does not flip.
- Finger-tapping, spiral, and oculomotor results all persist to `results/` (JSON + CSV index, git-ignored) via `core/session.py`.
- The oculomotor test flips the frame to selfie view, so calibration/target dots are drawn at fixed screen positions and the gaze sign is defined by calibration — no mirror convention is assumed in the gaze math. Gaze engine logic in `core/gaze/` is pure and unit-tested in `screening_tests/tests/test_gaze.py`.
- **All UI work must follow `docs/UI_STYLE_GUIDE.md`** (design tokens, components, motion, accessibility) — reference it in any screen or overlay change. The finger-tapping rework is planned in `docs/FINGER_TAPPING_REVISION_PLAN.md`.
- **Verification split:** Adam handles the "hard" verifications himself — anything needing the live app, camera, running launcher server, or browser interaction (launching tools, screenshotting the hub, camera-dependent tests). Codex does the "simple" ones it can do without live infra: syntax/lint checks, unit tests, static code review, and reasoning about the change. Don't start the launcher or drive Chrome to verify unless Adam explicitly asks.
